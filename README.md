# URL Shortener на Go

Сервис для сокращения ссылок с HTTP API, веб-интерфейсом и хранилищем на Redis.

## Что это

Учебный проект - URL shortener, который:
- Принимает длинный URL и возвращает короткий код.
- Редиректит по короткому коду на оригинальный URL.
- Дедуплицирует ссылки: одна и та же длинная ссылка всегда даёт один и тот же короткий код.
- Имеет простой веб-интерфейс для сокращения ссылок.
- Хранит данные в Redis (с персистентностью AOF + RDB).
- Умеет корректно завершаться (graceful shutdown).
- Полностью упакован в Docker (multi-stage build) и запускается одной командой.

## Стек

- **Go** - язык (стандартная библиотека `net/http`, без фреймворков, Go 1.22+ с method-based routing).
- **Redis** - хранилище (key-value) с включённым AOF для персистентности.
- **Docker / Docker Compose** - контейнеризация и запуск.
- **HTML/CSS/JS** - минималистичный веб-интерфейс без фреймворков.
- **go-redis/v9** - клиент Redis.
- **miniredis** - in-memory Redis для тестов.

## API

### POST /shorten

Принимает JSON с длинным URL, возвращает короткий код.

**Запрос:**
```json
{
  "url": "https://youtube.com/@nikolay_tuzov"
}
```
Ответ (200):

```json
{
  "short": "1"
}
```
Ошибки:

- 400 - невалидный URL или битый JSON.
- 500 - ошибка сервера (Redis недоступен и т.п.).

### GET /{short}
Редиректит (302) на оригинальный URL.

Пример:

```text
GET http://localhost:8080/1
→ 302 Location: https://youtube.com/@nikolay_tuzov
```
Ошибки:

- 400 - пустой short.
- 404 - short не найден.
- 500 - ошибка сервера.

### GET /
Отдаёт веб-интерфейс (web/index.html) для сокращения ссылок.

### GET /static/
Отдаёт статические файлы (CSS, JS) из папки web/.

## Как работает сокращение

Валидация URL (http/https, есть хост).
Проверка дедупликации: если URL уже сокращали - вернуть существующий short.
Если нет - получить новый ID через INCR url:sequence в Redis.
Закодировать ID в Base62.

Сохранить два ключа в Redis атомарно через TxPipelined:
- link:{short} - длинный URL (для редиректа).
- rev:{long} - короткий код (для дедупликации).

Почему два ключа: Redis - key-value, ключ - это направление поиска. Для редиректа нужен short → long, для дедупликации - long → short. Один ключ не даёт обе связи.

## Запуск
### Вариант 1: Docker Compose (рекомендуется)

```bash
make up
# или 
docker compose up --build
```

Поднимает и приложение, и Redis с персистентностью. 
Сервис доступен на http://localhost:8080/.

Остановить:
```bash
make down
# или
docker compose down
```

### Вариант 2: Локально
Поднять Redis:

```bash
docker run -d --name redis -p 6379:6379 redis:7-alpine
```
Запустить сервис:

```bash
go run ./cmd
```
Открыть в браузере http://localhost:8080/ или проверить через curl:

# Сократить ссылку
```bash
curl -X POST http://localhost:8080/shorten \
  -H "Content-Type: application/json" \
  -d '{"url":"https://youtube.com/@nikolay_tuzov"}'
```

# Перейти по короткому коду
```bash
curl -i http://localhost:8080/1
```

## Конфигурация
Адрес Redis читается из переменной окружения REDIS_ADDR (по умолчанию localhost:6379).
В docker-compose.yml задано redis:6379 - имя сервиса во внутренней сети Docker.

## Graceful shutdown

Сервер корректно завершается по SIGINT / SIGTERM:
Перестаёт принимать новые запросы.
Даёт активным запросам до 5 секунд на завершение.
Закрывает соединение с Redis.
Если мягкое завершение не удалось - жёсткое закрытие через server.Close().

## Middleware

- LoggingMiddleware - логирует метод, путь и длительность каждого запроса.
- RecoverMiddleware - ловит panic в хендлерах, возвращает 500, не роняя сервер.

Порядок: Recover → Logging → mux.

## Осознанные компромиссы

Зафиксированы осознанно, не являются багами:

- apperr смешивает ошибки разных слоёв (ErrNotFound - состояние storage, ErrInvalidURL - домен service). Плюс: единое место, handler не импортирует service. Минус: storage зависит от apperr. Пересмотреть, если storage будет переиспользоваться или apperr разрастётся.
- encodeBase62 кодирует строковое представление ID, а не число. Ссылки уникальны и работают, но длина short может скакать (например, id=10 → 3 символа, id=100 → 7 символов). Осознанно оставлено для простоты.
- TTL не задан - ссылки живут вечно. Осознанно (иначе дедупликация ломается после истечения). Пересмотреть, если понадобится автоочистка.
- INCR + Set не атомарны вместе - если Set упадёт после INCR, ID потрачен впустую (пропуск в нумерации).
- RecoverMiddleware не ловит panic в горутинах - только в основном потоке HTTP-сервера.
- Валидация URL отвергает хосты без точки (например, localhost). Для публичного shortener'а это нормально, но если нужно - проверку можно ослабить.

## Известные ограничения (не реализовано)

- Метрики (счётчик кликов через INCR) - не реализованы, чтобы не усложнять MVP.
- gRPC-транспорт - не реализован (один сервис, клиенты - браузеры; gRPC был бы искусственной нагрузкой).
- Kubernetes - не реализован (Docker Compose полностью покрывает потребности проекта).
- CI/CD - не настроен.
- Аутентификация - отсутствует (все ссылки публичные)
